# dimension-crew 기획서

> 최종 수정: 2026-09-11
> 이 문서만 읽어도 프로젝트 전체를 이해할 수 있도록 작성했다. 기획 대화에서 결정이 바뀌면 이 문서를 먼저 고친다.
> 표기: **[확정]** 매니저가 직접 요구하거나 선택한 것 / **[제안]** 기획 과정에서 제안됐고 최종 확인 전인 것 / **[미정]** 아직 정하지 않은 것

---

## 1. 개요

- **서비스**: 스테이디멘션 용현동 청소 파트타이머의 출퇴근, 객실 청소 체크, 급여 산정을 관리하는 모바일 웹앱과 어드민
- **사용자**
  - 청소 파트타이머 4~5명 (각자 본인 휴대폰으로 접속)
  - 총괄매니저 1명 (어드민, 슬랙 요청자)
- **규모**: 하루 청소 객실 8~9개 수준
- **목적**: 출퇴근·청소 기록과 인건비 산정을 자동화하고, 인건비를 기존 구글 시트로 문서화한다.
- **앱 표시 서비스명**: [미정] 레포명은 `dimension-crew`, 화면에 보일 한글 이름은 나중에 정한다.

## 2. 기술 스택 [제안, 진행 전제]

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트/서버 | Next.js (App Router) + TypeScript, PWA | 매니저가 이미 PicaPico 프로젝트에서 사용 중인 스택 |
| DB·인증·파일 | Supabase (Postgres, Storage) | 동일 이유, 무료 플랜으로 운영 가능 |
| 배포 | Railway | 동일 이유 |
| 슬랙 | Slack App (Events API, Interactivity) | 채널 메시지로 객실 등록, 버튼으로 공지 확인 |
| 구글 시트 | Google Sheets API (서비스 계정) | 기존 인건비 시트에 기록 |

- Supabase 무료 플랜은 활성 프로젝트 2개 제한이 있고, PicaPico가 1개를 쓰고 있다.
- 무료 프로젝트는 1주일 동안 사용이 없으면 일시정지된다. 매일 쓰는 앱이라 보통 문제없지만 장기 휴무 시 주의.

## 3. 알바 화면 흐름

### 3.1 로그인 [제안]
- 계정은 어드민이 생성한다. [확정]
- QR만으로는 사용자를 식별할 수 없으므로, 첫 접속 때 **전화번호 + PIN 4자리**로 1회 로그인하고 휴대폰에 세션을 유지한다.

### 3.2 출근 [확정, 2026-09-12 플로우 확정]
1. 홈 화면(하단 "홈" 탭)에서 오늘 출근 여부(출근 전/출근 중)를 확인하고 **"QR 스캔하기"** 버튼을 누른다.
2. 앱 안에서 카메라가 열리고, 숙소 입구의 QR을 비추면 인식된다. (인식 전까지는 다음 단계로 넘어가지 않는다)
3. 인식되면 "OO님, 출근하셨나요?" 확인 화면이 뜬다 (퇴근 확인과 동일하게, 자동으로 바로 처리하지 않고 확인을 받는다).
4. "출근 확인" 버튼을 누르면 출근 처리되고 "출근 처리되었습니다" 문구가 뜬다.
5. 같은 화면 바로 아래에 오늘 배정된 객실을 **타입 요약만 간단히** 보여준다 (번호·타입 뱃지 나열). 체크·사진 등 실제 작업은 하단 "청소" 탭(3.3)에서 한다.

- **QR을 앱 안 카메라 스캔으로만 인식하도록 변경** [확정, 2026-09-12]: 원래 QR에 `/checkin` 링크를 넣어뒀는데, 이러면 링크만 알면(주소창에 입력하거나 홈 화면 버튼으로) 실제로 QR을 찍지 않고도 출근·퇴근 처리가 가능한 허점이 있었다 (예: 집에서 퇴근 버튼만 눌러 퇴근 처리). 이를 막기 위해 QR에는 링크 대신 **토큰 문자열**(`settings.qr_token`)을 넣고, 앱 안의 "QR 스캔하기" 버튼으로 연 카메라가 그 문자열을 직접 인식했을 때만 출근/퇴근 처리가 진행되도록 했다. 링크가 아니므로 휴대폰 기본 카메라로 찍어도 아무 동작이 없다.
  - 잔여 한계: QR 스티커를 사진으로 찍어 다른 화면에 띄워놓고 그 화면을 다시 스캔하는 것까지는 막을 수 없다 (기존에도 있던 한계). 스티커를 아무나 접근 못 하는 곳에 두는 정도로 충분하다고 판단.
- QR은 출근·퇴근 공용 1개. 오늘 출근 기록이 없으면 출근, 있으면 퇴근 확인으로 분기한다. [제안]
- **GPS 위치 확인: 완전히 제거함** [확정, 2026-09-12]: 원래 "고정 QR은 사진으로 찍어두면 숙소 밖에서도 스캔할 수 있다"는 이유로 GPS 반경 확인을 넣었으나, 알바 인원이 적고(4~5명) 현장에서만 QR을 찍는 구조라 매니저가 불필요하다고 판단해 기능 자체와 관련 DB 컬럼을 삭제했다(`supabase/schema_drop_gps.sql`). 위치 권한을 요청하지 않고, 출퇴근 기록에 위치 데이터도 남기지 않는다. (대신 QR 자체를 앱 안 스캔 전용으로 바꿔 부정 출퇴근을 막는다.)

### 3.3 청소 체크 [확정, 2026-09-12 UI 확정]
- 객실 리스트는 표 형태: 순번 / 방번호 / 청소전↔청소완료 버튼 / 사진 버튼(사진이 있으면 초록색, 없으면 회색).
- "청소전" 버튼과 "사진" 버튼 둘 다 누르면 동일한 사진 관리 모달이 열린다 (이미 완료된 방도 다시 눌러서 사진 추가·삭제 가능).
- 모달 안에서 카메라로 사진을 찍어 올리고, 올린 사진은 본인이 삭제할 수 있다.
- **사진은 객실/욕실로 구분해서 각 1장씩, 최대 2장** [확정, 2026-09-12]. 모달에 "객실"/"욕실" 두 칸이 따로 있고 칸별로 촬영·삭제한다 (별도 화면으로 들어가지 않고 한 모달 안에서 처리).
- "사진 촬영 완료" 버튼을 누르면 (아직 완료 처리 전이었다면) 청소완료로 전환되고 완료 체크 시각이 기록된다. 이미 완료된 방이면 시각은 바뀌지 않는다(사진만 추가/삭제한 것이므로 청소 소요시간 계산에 영향 없음).
- 사진은 업로드 전 휴대폰에서 장당 약 200KB로 압축한다. [제안, 아직 미구현 — 서버는 원본 그대로 저장 중]
- 청소완료 시 슬랙 채널(#청소-배정)로 "OO호 청소가 완료되었습니다" 알림이 자동 전송된다 (4.6.1).

### 3.4 객실 추가·미완료 처리 [확정: 추가 기능 필요 / 세부는 제안]
시간이 남거나 다 끝내지 못하는 경우가 있어서 필요하다.
- **"+ 객실 추가"**: 시간이 남은 알바가 직접 객실을 추가한다. 추가분은 어드민 승인 화면에 따로 표시된다.
- **"미완료로 넘기기"**: 못 끝낸 객실을 다른 알바나 다음 날로 이월한다. (사진 관리 모달 안에 있는 링크로 접근)
- 어드민에서도 당일 객실 추가와 재배정이 가능하다.

### 3.5 퇴근 [확정]
1. 같은 QR을 스캔하면 "퇴근하시겠습니까?" 확인이 뜬다.
2. "퇴근 확인"을 누르면 퇴근 처리된다.
3. "퇴근 처리되었습니다. 오늘도 수고했습니다!" 문구와 함께 오늘 총 근무시간과 근무비용이 표시된다.

### 3.6 캘린더·입금액 조회 [확정]
- 캘린더의 근무일에 **금액**이 표시되고, 금액을 누르면 **근무시간**이 나온다.
- **이번 달 예상 입금액** = 이번 달 전체 알바비 × (1 − 0.033)
- 승인 전 근무를 예상 입금액에 포함할지는 [미정].

### 3.7 하단 메뉴 [확정, 2026-09-12]
- 알바 화면 하단 탭 구성: **홈 / 청소 / 캘린더**.
- 홈 화면은 "출근 전/출근 중" 상태만 보여주는 대시보드이고, 실제 출근·퇴근 처리는 "QR 스캔하기" 버튼 → 카메라 스캔(3.2)을 거쳐야만 가능하다. 홈 화면 자체에는 출근/퇴근 확인 버튼이 없다 (집에서 그냥 눌러서 퇴근 처리되는 걸 막기 위함).
- **오늘 한 번도 출근하지 않았으면 하단 탭 자체가 보이지 않는다** [확정, 2026-09-12]. 첫 출근 QR 스캔·확인을 마쳐야 하단 탭(홈/청소/캘린더)이 나타난다. 아직 출근 전인 알바가 청소 탭으로 건너뛰어 방 작업을 시작하는 걸 막기 위함.

## 4. 어드민

### 4.1 알바 계정 [확정]
- 계정 생성 (이름, 전화번호, PIN). 비활성화 기능 포함 [제안].

### 4.2 시급 [확정]
- 시급을 입력·변경할 수 있어야 한다.
- 사람마다 시급이 다른지 [미정]. 변경 시 과거 근무에 소급되지 않도록 적용 시작일을 함께 저장한다. [제안]
- 최저시급 미만 입력 시 경고를 띄운다. 기준 금액은 연도별 설정값으로 둔다. [제안]

### 4.3 근무 승인 [확정]
- 알바 근무가 완료되면 어드민이 승인한다.
- 승인 화면에 출퇴근 시각, 완료 객실, 사진, 추가·미완료 객실을 함께 보여준다. [제안]
- 어드민이 출퇴근 시각을 수정할 수 있게 할지 [미정].

### 4.4 객실 배정 [확정: 어드민이 사람별로 배정]
- 기본 경로는 슬랙 메시지 등록 (5.1 참고).
- 어드민 화면에서도 직접 입력·재배정할 수 있다. 슬랙 장애 대비. [제안]
- 이름 없이 등록된 객실은 "미배정" 칸에 모이고, 어드민이 사람별로 배정한다.

### 4.5 전체 비용·일정 [확정]
- 전체 알바의 비용과 일정을 **달력형**과 **리스트형** 두 가지로 본다.

### 4.6 알바별 청소 기록 [확정: 매니저가 반드시 볼 수 있어야 함 / 세부는 제안]
- 알바 이름을 누르면 날짜별 청소 객실, 완료 시각, 사진이 나온다.
- 배정 객실, 본인 추가 객실, 미완료로 넘긴 객실을 구분 표시한다.
- 필터: 기간(이번 주 / 이번 달 / 직접 선택), 알바, 객실 번호. 예: "301호를 이번 달에 누가 몇 번 청소했나"
- 월별 요약: 알바별 청소 객실 수, 근무시간, 객실당 평균 청소시간
- 객실당 청소시간은 알바가 별도 "시작" 버튼을 누르지 않고, 완료 체크 시각 사이의 간격(첫 객실은 출근 시각 기준)으로 자동 계산한다.

### 4.6.1 슬랙 청소완료 알림 [완료, 배포·테스트 완료 2026-09-12]
- 알바가 객실 청소를 완료 처리하면(사진 업로드 포함) 슬랙 채널로 "✅ OO호 청소가 완료되었습니다. (이름)" 메시지를 자동 전송한다.
- 매니저가 앱을 안 열어도 슬랙에서 청소 진행 상황을 실시간으로 확인할 수 있게 하기 위함.
- 채널: **#스테이디멘션-운영방** (환경변수 `SLACK_ROOM_CHANNEL_ID`로 지정. 5.1 계획 당시엔 `#청소-배정`으로 가정했으나 실제로는 운영방 채널 하나로 통일).
- 슬랙 앱(Bot Token, `chat:write` 권한) 생성 및 Railway 환경변수(`SLACK_BOT_TOKEN`, `SLACK_ROOM_CHANNEL_ID`) 등록 완료, 이성훈님 실제 청소 완료로 실전 테스트 성공(2026-09-12).

### 4.6.2 슬랙 출퇴근 알림 [완료, 배포 2026-09-12]
- 알바가 출근하면 슬랙 채널로 "🟢 OO님 출근했습니다 (HH:MM)" 전송.
- 알바가 퇴근하면 슬랙 채널로 "🔴 OO님 퇴근했습니다 (HH:MM)" + **오늘 그 알바가 완료한 방 목록** 함께 전송.
- 퇴근 알림 메시지에 **어드민 출퇴근 관리 화면 링크**(`/admin`) 포함 — 매니저가 슬랙에서 바로 승인 화면으로 이동 가능.
- 채널: `#스테이디멘션-운영방` (환경변수 `SLACK_ROOM_CHANNEL_ID`, 4.6.1과 동일 채널 사용).

### 4.7 객실 정보 [제안]
- 객실 번호와 타입(스탠다드룸 등)을 미리 등록해두고, 슬랙에서 번호만 보내도 자동 매칭한다.

### 4.8 사진 보관 [제안]
- 사진은 **90일 보관 후 자동 삭제**, 청소 기록(텍스트)은 영구 보관.
- 어드민에서 "보관" 표시한 사진은 삭제 대상에서 제외.
- 이유: 청소 품질 문제는 보통 며칠 안에 드러나고, 90일 보관이면 Supabase 무료 저장공간(1GB) 안에서 계속 운영 가능하다. 사진을 영구 보관하면 3~4개월 후 유료 플랜이 필요하다.
- 용량 추정: 하루 최대 45장 × 200KB × 30일 ≈ 월 270MB

## 5. 슬랙 연동

### 5.1 객실 등록·배정 [보류 — 슬랙 대신 어드민 화면 사용하기로 결정, 2026-09-12]
슬랙 메시지로 객실을 등록·배정하는 기능은 만들지 않기로 했다. 이유: `/admin/assignments`(어드민 객실 배정 화면)가 이미 있고 매니저가 그걸로 직접 배정하는 걸로 충분하다고 판단. 슬랙 Events API 연동(추가 스코프, Signing Secret, 매니저 슬랙 계정 확인 등)까지 만들 실익이 적음.

- 대신 매일 객실 배정은 **어드민 화면(`/admin/assignments`)에서 직접** 한다.
- 아래는 참고용으로 남겨두는 원래 구상(미구현):

```
9/12
김알바 301 302 303
이알바 401 402 405
```

### 5.2 인건비 구글 시트 입력 [완료, 어드민 버튼 방식으로 배포·실전 테스트 성공 2026-09-12]
- **대상 탭 확정**: `매입)인건비` 탭 (스프레드시트 `197I75...mhPYQ` 안의 별도 탭, `QR출퇴근기록` 탭과는 다름).
- **컬럼 구조 확정**: A=작성자, B=입금요청, C=요청금액(최종금액), D=업무명, E=(미사용), F=이름, G=주민등록번호(절대 건드리지 않음), H=시급, I=근무일정, J=근무시간.
- **동작 방식** [2026-09-12 수정: 행 자동 생성 허용]: 어드민 "출퇴근 관리" 화면에서 퇴근 완료된 근무 옆에 **"급여장부 입력" 버튼**을 누르면:
  - 그 알바 이름(F열)과 일치하면서 시급(H열)이 비어있는 행이 이미 있으면 → 그 행의 H(시급)·I(근무일정)·J(근무시간)만 채운다.
  - 일치하는 행이 없으면 → **새 행을 만들어 이름(F)·시급(H)·근무일정(I)·근무시간(J)만 자동으로 채운다.** 작성자·입금요청·요청금액·업무명(A~D열)과 주민등록번호(G열)는 비워두고, 매니저가 실제 입금을 요청할 때 직접 채운다. (초기에는 "미리 이름 적힌 빈 행이 있어야만 동작"하는 방식이었으나, 매번 시트에 미리 이름을 적어둬야 하는 게 번거롭다는 피드백으로 자동 생성 방식으로 변경함.)
  - I열(근무일정) 형식: `11:00 ~ 15:00 (휴게 없음)` — 휴게시간은 항상 없음으로 고정.
  - J열(근무시간) 형식: 10분 단위로 반올림한 뒤 소수로 표기 (예: 3시간 29분 → 3.5).
  - 한 번 입력된 근무는 `shifts.payroll_row`에 기록해 중복 입력을 막는다.
- 승인된 근무만 기록할지는 [미정] — 현재는 어드민이 판단해서 버튼을 누르는 방식이라 승인 여부와 무관하게 동작함.

### 5.2.1 인건비 월별 자동 알림 [완료, 배포 2026-09-12, 외부 설정·실전 테스트 완료 2026-09-13]
지급주기(6절)에 맞춰 매월 4일(또는 그 전 영업일)에 매니저 개인 슬랙 DM으로 그 사이클 인건비 요약을 자동으로 보낸다.

  >

  > • 김OO: 18.0시간 · 162,000원
  >
  > **합계: 382,500원**

  > [ 입력 완료 → 공지하기 ]

- **중복 방지**: `sheet_exports.reminder_sent_at`에 사이클별로 기록, 이미 보낸 사이클은 다시 안 보냄.
- **필요한 환경변수**: `SLACK_MANAGER_USER_ID`(DM 받을 매니저의 슬랙 사용자 ID), `SLACK_SIGNING_SECRET`(슬랙 요청 검증), `DATA_GO_KR_HOLIDAY_API_KEY`, `CRON_SECRET`(외부 크론이 보낼 토큰).

- **참고**: 이 기능의 외부 설정(슬랙 Interactivity, 환경변수, 공휴일 API 키, 외부 크론 등록)이 2026-09-13에 완료되었는데, 그 시점에 이미 2026-09월 사이클(9/4 알림일)이 지나 있어서 **9월 사이클은 자동 DM이 발송되지 않았다** — 이 사이클은 어드민 화면에서 수동으로 확인/입력. 다음 사이클(10/4 또는 그 전 영업일)부터 정상적으로 자동 발송된다.

### 5.4 운영방 PM 봇 (일일 체크리스트 + 대화형 확정) [완료, 배포·실전 테스트 완료 2026-09-15]
청소·근태와 무관한 운영 전반의 할 일(예: "도배 완료", "에어컨 금액 확인" 등)을 매일 아침 슬랙 운영방에 PM처럼 브리핑하고, **매니저가 그 채널에 남기는 답장을 실제로 읽어** 동의/이견을 판단해 계획을 다시 정리해 되묻는 대화형 봇. (최초 버전은 `manage_emp` PR #1에서 가져온 일방향 요약 봇이었으나, 매니저 답장을 실제로 반영하지 않는 구조였던 것을 확인하고 2026-09-15에 아래와 같이 대화형으로 다시 설계함.)

- **아침 브리핑** (`GET /api/cron/daily-checklist` 또는 `?phase=morning`, 크론): `checklist_items` 현황 + 최근 운영방 대화(최대 50개)를 Claude에 보내 "오늘 할 일 / 다음 일정 / 대화에서 새로 파악한 내용"을 정리한 메시지를 생성해 운영방에 게시하고, 마지막에 확정 여부를 묻는다. 이 내용을 `checklist_daily_plan`(날짜별 1행)에 `status=pending`으로 저장.
- **저녁 리포트** (`GET /api/cron/daily-checklist?phase=evening`, 크론) [2026-09-22 추가]: 그날 하루 나눈 대화 + 체크리스트 현황을 읽고 정리해서 보고만 한다 — **확인을 요청하지 않고, 매니저의 답장을 기다리지 않고 그대로 진행**된다(요청: "저녁엔 대화 내용을 다 읽고 그대로 보고하고 그대로 진행, 우리 답변은 들을 필요 없음"). 그래서 게시 즉시 `status=confirmed`로 저장한다(단, 이후에도 `@멘션`으로는 재수정 가능).
- **답장 처리** (`POST /api/slack/events`, 슬랙 Events API): 운영방에 새 메시지가 오면 슬랙이 실시간으로 호출. 오늘 날짜의 계획이 **`pending`**(아침 브리핑 후 확정 전)이면 일반 메시지에 반응해 Claude가 "동의"/"이견"을 판단하고, 동의면 `status=confirmed` + 짧은 확인 메시지, 이견이면 반영해 재정리 후 다시 게시(`revision` 증가, 상태는 다시 `pending`). **`confirmed`**(아침 확정 후, 또는 저녁 리포트 게시 직후)로 넘어간 뒤에는 일반 메시지에는 반응하지 않고, **봇을 `@멘션`했을 때만**(`app_mention` 이벤트) 그 의견을 반영해 계획을 다시 `pending`으로 열어 재정리한다 — 확정 후 아무 잡담에나 반응해 시끄러워지는 걸 막으면서도, 매니저가 원할 때 언제든 재수정할 수 있게 함. 오늘 브리핑/리포트를 아직 안 보냈으면 그냥 대화로 두고 반응하지 않는다.
- **상태를 자동으로 바꾸지 않음**: 이 봇은 대화를 통해 "오늘 뭘 할지"를 정리·공유하는 역할만 하고, `checklist_items`의 실제 상태·항목은 자동으로 바꾸지 않는다 — 항목 추가/상태 변경은 Supabase에서 직접 한다.
- **완료 항목 자동 숨김** [2026-09-22 추가]: 완료(done) 항목이 계속 브리핑에 남아 지저분해지는 걸 막기 위해, `completed_at`(완료 처리된 시각, DB 트리거로 자동 기록)이 완료 당일+다음날 저녁까지만 브리핑에 포함되고 그 이후엔 자동으로 빠진다(요청: "완료 상황은 다음날 저녁까지만 보이게 하고 그다음날부턴 완료내역에서 지워줘"). Supabase에서 삭제하는 게 아니라 브리핑 표시에서만 제외된다 — 데이터 자체는 남아있다.
- **인증/드라이런**: 크론은 다른 cron과 동일하게 `?token=CRON_SECRET`(저녁은 `&phase=evening` 추가). `?dryRun=1`이면 샘플 데이터로 실제 전송·저장 없이 메시지 형태만 확인(로컬은 `npm run simulate` — 아침/답장/저녁까지 전부 시뮬레이션). 이벤트 엔드포인트는 슬랙 서명(`SLACK_SIGNING_SECRET`, 5.2.1/5.3과 공용)으로 검증.
- **모델: `claude-sonnet-5`** [2026-09-22 변경, 원래 `claude-opus-5`]: 체크리스트 요약/동의-이견 판단은 복잡한 추론이 필요 없는데, opus 모델로 하루 2번(아침·저녁) 자동 호출만으로 Anthropic 크레딧 $5가 약 7일 만에 소진됨(하루 평균 약 $0.71) — 매니저 요청으로 비용이 약 2.5배 저렴한 sonnet-5로 전환. `output_config.effort: "low"`도 함께 적용해 추가 절감.
- **필요한 환경변수**: `SLACK_BOT_TOKEN`(공용, `chat:write`+`channels:history`/`groups:history`+`app_mentions:read` 권한 필요), `SLACK_OPERATIONS_CHANNEL_ID`, `SLACK_SIGNING_SECRET`(공용), `CRON_SECRET`(공용), `ANTHROPIC_API_KEY`(없으면 브리핑/리포트는 스텁 메시지로, 답장 재정리는 동작하지 않고 확정 키워드 감지만 됨).
- **[미정]**: `/admin/checklist` 같은 관리 화면은 아직 없음 — 체크리스트 항목 추가/상태 변경은 현재 Supabase에서 직접 해야 한다. 필요하면 어드민 화면을 별도로 만들지 매니저 확인 필요. 다른 슬랙 채널(예: 마케팅방)에서도 쓰고 싶다는 요청이 있었으나, 채널별로 체크리스트를 분리하는 구조 변경은 2026-09-16에 일단 보류함(먼저 멘션 재수정 기능만 반영).
- **실전 테스트 완료(2026-09-15)**: Supabase 3개 SQL 실행, Slack App(`channels:history`/`groups:history` 권한, Event Subscriptions `message.channels` 구독) 설정·재설치, Railway 환경변수(`SLACK_OPERATIONS_CHANNEL_ID`, `ANTHROPIC_API_KEY` 포함) 등록, 실제 크론 호출로 운영방에 브리핑 게시 확인, 답장에 봇이 실시간으로 반응하는 것까지 확인 완료. **2026-09-16 추가**: 확정 후 `@멘션`으로 재수정하는 기능 반영. **2026-09-22 추가**: 저녁 리포트(`phase=evening`) 모드와 모델을 sonnet-5로 전환하는 코드 반영 완료 — 저녁 phase 실전 테스트와 cron-job.org에 아침/저녁 2개 등록이 아직 남음 — 자세한 순서는 `SETUP.md` 8번 참고.
