# dimension-crew 기획서

> 최종 수정: 2026-09-11
> 이 문서만 읽어도 프로젝트 전체를 이해할 수 있도록 작성했다. 기획 대화에서 결정이 바뀌면 이 문서를 먼저 고친다.
> 표기: **[확정]** 매니저가 직접 요구하거나 선택한 것 / **[제안]** 기획 과정에서 제안됐고 최종 확인 전인 것 / **[미정]** 아직 정하지 않은 것

## 1. 개요

- **서비스**: 스테이디멘션 용현동 청소 파트타이머의 출퇴근, 객실 청소 체크, 급여 산정을 관리하는 모바일 웹앱과 어드민
- **사용자**
  - 청소 파트타이머 4~5명 (각자 본인 휴대폰으로 접속)
  - 총괄매니저 1명 (어드민, 슬랙 요청자)
- **규모**: 하루 청소 객실 8~9개 수준
- **목적**: 출퇴근·청소 기록과 인건비 산정을 자동화하고, 인건비를 기존 구글 시트로 문서화한다.
- **앱 표시 서비스명**: [미정] 레포명은 `dimension-crew`, 화면에 보일 한글 이름은 나중에 정한다.

## 2. 기술 스택 [제안, 진행 전제]

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트/서버 | Next.js (App Router) + TypeScript, PWA | 매니저가 이미 PicaPico 프로젝트에서 사용 중인 스택 |
| DB·인증·파일 | Supabase (Postgres, Storage) | 동일 이유, 무료 플랜으로 운영 가능 |
| 배포 | Railway | 동일 이유 |
| 슬랙 | Slack App (Events API, Interactivity) | 채널 메시지로 객실 등록, 버튼으로 공지 확인 |
| 구글 시트 | Google Sheets API (서비스 계정) | 기존 인건비 시트에 기록 |

- Supabase 무료 플랜은 활성 프로젝트 2개 제한이 있고, PicaPico가 1개를 쓰고 있다.
- 무료 프로젝트는 1주일 동안 사용이 없으면 일시정지된다. 매일 쓰는 앱이라 보통 문제없지만 장기 휴무 시 주의.

## 3. 알바 화면 흐름

### 3.1 로그인 [제안]
- 계정은 어드민이 생성한다. [확정]
- QR만으로는 사용자를 식별할 수 없으므로, 첫 접속 때 **전화번호 + PIN 4자리**로 1회 로그인하고 휴대폰에 세션을 유지한다.

### 3.2 출근 [확정]
1. 숙소에 붙은 지정 QR을 본인 휴대폰으로 스캔하면 웹앱이 열린다.
2. 출근 처리된다.
3. "김알바님 환영합니다" 메시지가 뜬다.
4. 오늘 본인에게 배정된 객실 리스트가 "301호 스탠다드룸" 형식으로 뜬다.

- QR은 출근·퇴근 공용 1개. 오늘 출근 기록이 없으면 출근, 있으면 퇴근 확인으로 분기한다. [제안]
- **부정 출근 방지** [제안]: 고정 QR은 사진으로 찍어두면 숙소 밖에서도 스캔할 수 있다. 출퇴근 시 GPS로 숙소 반경 내인지 확인하고, 어드민 승인으로 한 번 더 거른다. 반경 값은 [미정].

### 3.3 청소 체크 [확정]
- 객실별로 청소가 끝나면 완료 체크하고 사진을 남긴다.
- 사진은 업로드 전 휴대폰에서 장당 약 200KB로 압축한다. [제안]
- 객실당 사진 장수: 1장 기준으로 설계. [미정]
- 완료 체크 시각을 기록한다.

### 3.4 객실 추가·미완료 처리 [확정: 추가 기능 필요 / 세부는 제안]
시간이 남거나 다 끝내지 못하는 경우가 있어서 필요하다.
- **"+ 객실 추가"**: 시간이 남은 알바가 직접 객실을 추가한다. 추가분은 어드민 승인 화면에 따로 표시된다.
- **"미완료로 넘기기"**: 못 끝낸 객실을 다른 알바나 다음 날로 이월한다.
- 어드민에서도 당일 객실 추가와 재배정이 가능하다.

### 3.5 퇴근 [확정]
1. 같은 QR을 스캔하면 "퇴근하시겠습니까?" 확인이 뜬다.
2. 확인을 누르면 퇴근 처리된다.
3. 오늘 총 근무시간과 근무비용이 산정되어 표시된다.

### 3.6 캘린더·입금액 조회 [확정]
- 캘린더의 근무일에 **금액**이 표시되고, 금액을 누르면 **근무시간**이 나온다.
- **이번 달 예상 입금액** = 이번 달 전체 알바비 × (1 − 0.033)
- 승인 전 근무를 예상 입금액에 포함할지는 [미정].

## 4. 어드민

### 4.1 알바 계정 [확정]
- 계정 생성 (이름, 전화번호, PIN). 비활성화 기능 포함 [제안].

### 4.2 시급 [확정]
- 시급을 입력·변경할 수 있어야 한다.
- 사람마다 시급이 다른지 [미정]. 변경 시 과거 근무에 소급되지 않도록 적용 시작일을 함께 저장한다. [제안]
- 최저시급 미만 입력 시 경고를 띄운다. 기준 금액은 연도별 설정값으로 둔다. [제안]

### 4.3 근무 승인 [확정]
- 알바 근무가 완료되면 어드민이 승인한다.
- 승인 화면에 출퇴근 시각, 완료 객실, 사진, 추가·미완료 객실을 함께 보여준다. [제안]
- 어드민이 출퇴근 시각을 수정할 수 있게 할지 [미정].

### 4.4 객실 배정 [확정: 어드민이 사람별로 배정]
- 기본 경로는 슬랙 메시지 등록 (5.1 참고).
- 어드민 화면에서도 직접 입력·재배정할 수 있다. 슬랙 장애 대비. [제안]
- 이름 없이 등록된 객실은 "미배정" 칸에 모이고, 어드민이 사람별로 배정한다.

### 4.5 전체 비용·일정 [확정]
- 전체 알바의 비용과 일정을 **달력형**과 **리스트형** 두 가지로 본다.

### 4.6 알바별 청소 기록 [확정: 매니저가 반드시 볼 수 있어야 함 / 세부는 제안]
- 알바 이름을 누르면 날짜별 청소 객실, 완료 시각, 사진이 나온다.
- 배정 객실, 본인 추가 객실, 미완료로 넘긴 객실을 구분 표시한다.
- 필터: 기간(이번 주 / 이번 달 / 직접 선택), 알바, 객실 번호. 예: "301호를 이번 달에 누가 몇 번 청소했나"
- 월별 요약: 알바별 청소 객실 수, 근무시간, 객실당 평균 청소시간
- 객실당 청소시간은 알바가 별도 "시작" 버튼을 누르지 않고, 완료 체크 시각 사이의 간격(첫 객실은 출근 시각 기준)으로 자동 계산한다.

### 4.7 객실 정보 [제안]
- 객실 번호와 타입(스탠다드룸 등)을 미리 등록해두고, 슬랙에서 번호만 보내도 자동 매칭한다.

### 4.8 사진 보관 [제안]
- 사진은 **90일 보관 후 자동 삭제**, 청소 기록(텍스트)은 영구 보관.
- 어드민에서 "보관" 표시한 사진은 삭제 대상에서 제외.
- 이유: 청소 품질 문제는 보통 며칠 안에 드러나고, 90일 보관이면 Supabase 무료 저장공간(1GB) 안에서 계속 운영 가능하다. 사진을 영구 보관하면 3~4개월 후 유료 플랜이 필요하다.
- 용량 추정: 하루 최대 45장 × 200KB × 30일 ≈ 월 270MB

## 5. 슬랙 연동

### 5.1 객실 등록·배정 [확정: 슬랙으로 보내면 자동 등록 / 포맷은 제안]
전용 채널(예: `#청소-배정`, 이름 [미정])에 전날 밤이나 당일 아침에 올린다.

```
9/12
김알바 301 302 303
이알바 401 402 405
```

- 첫 줄은 날짜, 다음 줄부터 `이름 객실번호...`
- 이름 없이 번호만 있는 줄은 미배정으로 등록
- 등록되면 봇이 요약 답장: `9/12 객실 6개 등록 · 김알바 3 / 이알바 3`
- 없는 객실 번호나 등록되지 않은 이름은 해당 줄만 경고
- 이미 출근한 알바 화면에 즉시 반영
- 같은 날짜로 다시 올렸을 때 덮어쓸지 추가할지 [미정]
- 매니저의 슬랙 계정에서 온 메시지만 처리한다. [제안]

### 5.2 인건비 구글 시트 입력 [확정]
- 매니저가 슬랙으로 요청하면 **기존 구글 시트**에 인건비를 입력한다.
- 시트 링크와 컬럼 구조는 개발 들어갈 때 매니저가 전달한다. **반드시 요청해서 받을 것.**
- 요청 형식 예: `인건비입력 9월` [제안]
- 승인된 근무만 기록한다. [제안]

### 5.3 입력 완료 공지 [확정]
- 시트 입력이 끝난 시점에 매니저가 슬랙으로 요청하면, 지정 채널로 메시지를 보낸다.
  - 예: "이번 달 인건비 입력이 완료되었습니다"
- 구현 제안: 시트 입력이 끝나면 봇이 매니저에게 "채널에 공지할까요?" 버튼을 보내고, 누르면 지정 채널로 전송. [제안]
- 공지 채널명 [미정]

## 6. 급여 계산 규칙

| 항목 | 규칙 | 상태 |
|---|---|---|
| 일 근무시간 | 퇴근 시각 − 출근 시각 | 확정 |
| 일 근무비용 | 근무시간 × 시급 | 확정 |
| 월 예상 입금액 | 월 합계 × (1 − 0.033) | 확정 |
| 시간 단위 처리 | 분 단위 반올림/절사 여부 | 미정 |
| 휴게시간 | 차감 여부 | 미정 |
| 원 단위 절사 | 10원/1원 단위 | 미정 |
| 공제율 | 코드에 하드코딩하지 않고 설정값으로 | 제안 |

**노무 확인 필요**: 시급제로 출퇴근까지 기록·관리하면 3.3% 사업소득(프리랜서)이 아니라 근로자로 볼 여지가 있고, 주 15시간 이상 근무 시 주휴수당 문제가 생길 수 있다. 매니저에게 세무사·노무사 확인을 권했다. 결과에 따라 공제 방식이 바뀔 수 있으므로 계산 로직을 설정값으로 분리해둔다.

## 8. 개발 순서 [제안]

1. **1단계 (핵심 앱)**: 로그인, QR 출퇴근, 객실 체크·사진, 객실 추가·미완료, 급여 계산·캘린더, 어드민(계정·시급·배정·승인·달력/리스트·알바별 기록)
2. **2단계**: 슬랙 채널 메시지로 객실 등록·배정
3. **3단계**: 슬랙 요청 → 구글 시트 입력 → 채널 공지

### 8.1 1단계 내부 순서 (2026-09-11 확정)

1단계 자체도 범위가 커서, 매니저와 합의해 아래 순서로 쪼갠다.

1. **1-1 출퇴근** [완료, 배포됨]: 로그인(전화번호+PIN), QR 출퇴근(GPS 확인), 급여 계산·캘린더, 어드민(계정·시급이력·GPS/공제 설정·근무 승인). 구글 시트 자동 기록(새 탭)도 이 단계에 포함 — 매니저가 바로 쓸 수 있어야 해서 슬랙 연동(3단계) 전이지만 먼저 넣는다. Railway 배포 완료(2026-09-11).
2. **1-2 객실 청소** [완료, 배포됨]: 객실 체크·사진, 객실 추가·미완료 처리, 어드민 객실 배정·알바별 청소 기록. Railway 배포 및 실사용 테스트 완료(2026-09-12).

객실 관련 화면(3.3, 3.4, 4.4, 4.6, 4.7, 4.8)은 1-2에서 작업한다.

## 9. 개발 전에 매니저에게 받을 자료

- [x] 객실 번호·타입 전체 목록 (2026-09-11 확인, 총 16개실). 201~205호 프라이빗룸, 301·302·304·305·306호 스탠다드룸, 303호 릴렉스룸(싱글베드), 401~405호 도미토리룸. `supabase/schema_rooms.sql`에 시드 데이터로 반영.

- [x] 숙소 주소 (GPS 확인용) — 매니저가 "알아서 하라"고 위임 (2026-09-11). 좌표를 코드에 하드코딩하지 않고 **어드민 설정 화면에서 위도/경도를 직접 입력**하도록 구현. 실제 좌표는 배포 후 매니저가 입력해야 GPS 확인이 동작한다.
- [ ] 슬랙 워크스페이스 앱 설치 권한, 객실 배정 채널명, 인건비 공지 채널명 (2단계/3단계에서 필요)
- [ ] 구글 시트 링크와 기존 컬럼 구조 — 링크는 이미 확보(`STAY DIMANSION` 시트). 자동 기록은 새 탭 `QR출퇴근기록`에만 하므로 기존 컬럼 구조는 3단계(슬랙 연동)에서 다시 확인.
