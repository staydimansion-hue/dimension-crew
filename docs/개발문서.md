# dimension-crew 개발 문서

기획 배경과 요구사항 변경 이력은 `docs/기획서.md`, 최초 설치 절차는 `SETUP.md`를 참고하세요.
이 문서는 코드 구조와 동작 원리를 정리한 **개발자용 기술 문서**입니다.

## 1. 개요

STAY DIMANSION(인천 용현동) 파트타임 청소 인력의 QR 출퇴근 + 객실 청소 체크 + 급여 계산을 관리하는 사내 시스템입니다.

- **배포**: Railway (`dimension-crew-production-254e.up.railway.app`)
- **DB/스토리지**: Supabase (Postgres + Storage)
- **외부 연동**: Slack(알림/버튼), Google Sheets(급여장부 자동입력), 공공데이터포털(공휴일 판단)

## 2. 기술 스택

- Next.js 16 (App Router, Turbopack) + TypeScript
- Tailwind CSS v4
- Supabase (`@supabase/supabase-js`, service role 키로만 접근)
- 인증: `jose`(JWT) + `bcryptjs`(PIN/비밀번호 해시)
- QR: `qrcode`(생성, 관리자 화면) / `jsqr`(인식, 직원 카메라 스캔)
- Google Sheets: `googleapis` (JWT 서비스 계정)

## 4. 인증/세션

두 종류의 완전히 분리된 세션이 있습니다.

| 구분 | 로그인 방식 | 쿠키 | 보호 범위 |
|---|---|---|---|
| 직원 | 전화번호 + PIN(bcrypt) | `staff_session` (JWT, `STAFF_JWT_SECRET`) | `src/lib/staffSession.ts`가 각 API에서 개별 확인 |
| 관리자 | 아이디 + 비밀번호(bcrypt) | `admin_session` (JWT, `ADMIN_JWT_SECRET`) | `src/middleware.ts`가 `/admin/*`, `/api/admin/*` 전체를 일괄 차단 |

`/api/cron/*`, `/api/slack/*`는 미들웨어 보호 대상이 아니며, 각자 자체 인증을 합니다(`CRON_SECRET` 쿼리 토큰, 슬랙 서명 검증).

## 5. 데이터 모델 (Supabase)

`supabase/schema.sql` → `schema_rooms.sql` → `schema_photo_category.sql` → `schema_drop_gps.sql` → `schema_qr_token.sql` → `schema_payroll_row.sql` → `schema_sheet_exports.sql` 순서로 적용됩니다(SETUP.md 1번 참고).

- **staff**: 직원 마스터 (이름/전화번호/PIN 해시)
- **wage_rates**: 직원별 시급 이력 (`effective_from` 기준 최신값 사용)
- **admins**: 관리자 계정
- **settings**: 싱글톤(`id=1`) 설정 테이블 — `deduction_rate`(공제율), `min_wage_krw`, `qr_token`(카메라 스캔용 토큰). GPS 관련 컬럼은 `schema_drop_gps.sql`로 전부 삭제됨.
- **shifts**: 출퇴근 1건 = 1 row. `clock_in_at`/`clock_out_at`, `hours_worked`, `hourly_wage`, `amount`, `status`(`working`/`done`/`approved`), `sheet_row`(구글시트 QR출퇴근기록 탭 동기화된 행 번호), `payroll_row`(급여장부 탭에 입력된 행 번호, 미입력 시 null). 같은 직원이 동시에 열린 근무를 2개 가질 수 없도록 부분 유니크 인덱스(`clock_out_at is null`) 적용.
- **rooms**: 객실 마스터 (호수/타입)
- **room_tasks**: 특정 날짜(`work_date`)에 특정 방을 누가 청소하는지. `status`(`todo`/`done`/`carried_over`), `source`(`admin`/`self_added`/`slack` — 현재 슬랙 배정은 사용 안 함), 미완료 시 다음날로 이월하면 `carried_to_task_id`로 원본↔사본 연결.
- **task_photos**: `room_tasks` 1건당 최대 2장(`category`: `room`|`bathroom`), Supabase Storage 버킷 `task-photos`에 저장.
- **sheet_exports**: 인건비 알림 자동화의 멱등성 보장용. `cycle_key`(지급월)별로 `reminder_sent_at`/`announced_at` 기록.

## 6. 주요 기능 흐름

### 6.1 QR 출퇴근

QR은 URL이 아니라 **불투명한 랜덤 토큰**(`settings.qr_token`)을 인코딩합니다 — 프린트된 QR을 사진으로 찍어서 집에서 열어도 아무 동작이 없도록 하기 위함입니다(직원이 실제로 매장 QR을 카메라로 스캔해야만 동작).

1. `/checkin` 진입 시 `/api/staff/me`로 본인 `qrToken` 조회
2. `QrScanner`(`getUserMedia` + `jsQR`)가 카메라 프레임을 디코딩, `code.data === qrToken`이면 스캔 성공 처리
3. 스캔 성공 → `/api/attendance/status`로 현재 열린 근무 여부 확인 → 출근/퇴근 확인 화면 표시
4. 확인 버튼 → `POST /api/attendance/toggle` (GPS 없음, 서버가 `staff_session`으로 본인 식별) → 슬랙 알림 발송(`SLACK_ROOM_CHANNEL_ID`)
   - 출근: `🟢 {이름}님 출근했습니다 (HH:MM)`
   - 퇴근: `🔴 {이름}님 퇴근했습니다 (HH:MM)` + 당일 완료한 방 목록 + 관리자 승인 링크

홈(`/`)은 상태만 보여주는 대시보드이고, 실제 퇴근은 반드시 `/checkin`의 QR 스캔을 통해서만 가능합니다(URL 직접 이동으로 우회 불가).

### 6.2 객실 청소 체크

- `/rooms`에서 오늘 배정된 방 목록(`room_tasks`) 표시
- 방마다 "청소전 ↔ 청소완료" 토글 버튼 + 사진 버튼(객실/욕실 두 장 다 있으면 초록색)
- 사진은 모달에서 카테고리별로 촬영/삭제 가능, `POST /api/rooms/complete`로 완료 처리
- 완료 처리 시 슬랙으로 청소 완료 알림 발송
- 당일 미완료 방은 관리자 화면 또는 자동 로직으로 다음날 이월(`/api/rooms/carry-over`)

### 6.3 급여 계산 & 구글시트 연동

- 시급 × 근무시간 - 공제율(기본 3.3%) = `shifts.amount` (체크아웃 시 계산)
- 매 근무 기록은 구글시트 `QR출퇴근기록` 탭에 자동 동기화 (`src/lib/sheets.ts`, `sheet_row`로 중복 방지)
- 관리자 화면(`/admin`)에서 퇴근 완료된 근무에 대해 "급여장부 입력" 버튼 클릭 → `POST /api/admin/shifts/[id]/payroll` → `writePayrollEntry()`가 실제 인건비 대장(`매입)인건비` 탭)에 기록
  - F열=이름, H열=시급, I열=근무일정(`HH:MM ~ HH:MM (휴게 없음)`), J열=근무시간(10분 단위 반올림, 소수 시간 표기. 예: 3시간29분→3.5)
  - F열에 이름은 있는데 H열(시급)이 비어있는 행을 찾아 그 행에 채워 넣음
  - 매칭되는 행이 없으면 **새 행을 추가**(F/H/I/J만 채우고 A~E, G는 관리자가 나중에 수기 입력)
  - 입금요청(A~D)이나 주민등록번호(G)는 절대 건드리지 않음
- 시트 서식(`POST /api/admin/format-sheet` → `formatAttendanceSheet()`)으로 `QR출퇴근기록` 탭 헤더 색상/고정/열너비/테두리 일괄 적용 가능

### 6.4 슬랙 알림

- `src/lib/slack.ts`: `postSlackMessage()`(Bot Token으로 `chat.postMessage`), `verifySlackSignature()`(HMAC-SHA256, 5분 이내 요청만 허용)
- 출퇴근/청소완료 알림 → `SLACK_ROOM_CHANNEL_ID` (#스테이디멘션-운영방)
- 인건비 알림/공지 → 매니저 개인 DM(`SLACK_MANAGER_USER_ID`) → 버튼 클릭 시 `SLACK_PAYROLL_CHANNEL_ID`(#스테이디멘션-운영지원팀)에 공지

### 6.5 매월 인건비 자동 알림 (5.2.1/5.3)

지급 주기 규칙(`src/lib/payCycle.ts`): **매월 5일 ~ 다음달 4일** 근무분을 **다음달 5일**에 지급. `cycleKey`는 지급월(`YYYY-MM`) 기준.

1. 외부 크론(cron-job.org)이 매일 `GET /api/cron/payroll-reminder?token=CRON_SECRET` 호출
2. `previousBusinessDay()`(`src/lib/holidays.ts`, 공공데이터포털 "특일 정보" API로 주말+공휴일 판단)로 "이번 달 4일 또는 그 전 영업일"을 계산해 오늘과 비교, 아니면 스킵
3. 이미 보낸 알림이면(`sheet_exports.reminder_sent_at`) 스킵
4. 해당 지급 주기 근무 기록을 직원별로 합산해 Block Kit 메시지(합계 + "입력 완료 → 공지하기" 버튼) 생성 → 매니저 DM 발송 → `sheet_exports` upsert
5. 매니저가 버튼 클릭 → `POST /api/slack/interactions`(서명 검증) → `SLACK_PAYROLL_CHANNEL_ID`에 공지 발송 + `sheet_exports.announced_at` 기록

> 공공데이터포털 서비스키는 Encoding/Decoding 두 형태가 있는데, `holidays.ts`가 어느 쪽이 들어와도 내부적으로 디코딩 후 재인코딩하므로 둘 중 아무 값이나 넣어도 됩니다. 크론 라우트는 전체가 try/catch로 감싸져 있어 실패 시 빈 500 페이지 대신 JSON 에러 메시지로 원인을 알려줍니다.

## 7. API 라우트 요약

| 라우트 | 메서드 | 인증 | 설명 |
|---|---|---|---|
| `/api/staff/login`, `/logout`, `/me` | POST/GET | 직원 세션 발급/조회 | 전화번호+PIN 로그인 |
| `/api/attendance/status` | GET | 직원 세션 | 오늘 출근 여부, 열린 근무 여부 |
| `/api/attendance/toggle` | POST | 직원 세션 | 출근/퇴근 처리 + 슬랙 알림 |
| `/api/rooms/today`, `/complete`, `/photos`, `/photos/[id]`, `/carry-over`, `/add` | GET/POST/DELETE | 직원 세션 | 오늘 배정 조회/완료 처리/사진 업로드·삭제/이월/자율 추가 |
| `/api/staff/calendar` | GET | 직원 세션 | 본인 근무 캘린더 |
| `/api/admin/*` | 각각 | 관리자 세션(미들웨어) | 직원/객실/배정/근무/설정 CRUD, 급여장부 입력, 시트 서식 |
| `/api/slack/interactions` | POST | 슬랙 서명 검증 | 슬랙 버튼(Block Actions) 콜백 |
| `/api/cron/payroll-reminder` | GET | `?token=CRON_SECRET` | 매월 인건비 알림 발송 |

## 9. 배포

Railway가 `main` 브랜치 push를 자동 배포합니다. `redeploy` 버튼은 재빌드 없이 마지막 빌드를 재시작만 하므로, 새 커밋 반영 여부는 GitHub 커밋 SHA와 Railway 빌드 SHA를 비교해서 확인하세요. 배포 후 QR 내용(토큰)이 바뀌면 `/admin/qr`에서 QR을 다시 인쇄해 교체해야 합니다.
